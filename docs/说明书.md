# Mori Classroom 产品说明书（研发原型 v0.1，2026-10-17）

## 1. 它解决什么
经管课里“出口报价”这类知识点，学生常见两类问题：会背公式但把**成本加成率当成毛利率**；会算价格但**说不清条件、回应不了买家顾虑**。Mori Classroom 把“讲解 → 有依据的答疑 → 模拟磋商 → 可复算的反馈 → 针对错误复练”放在一个 8–10 分钟的流程里。

## 2. 谁用、怎么用
已学过基础概念的经管本科生（需教师确认）。打开 https://pkusi.com/human/ ，无需账号：

1. **课程入口**：看学习目标、材料范围（每条资料标明“虚构课堂规则 / 公开来源”）、服务实时状态。点“开始学习”才开启声音；不请求麦克风或摄像头。
2. **学习工作台**（左：数字人与控制；中：当前任务；右：对话与出处）
   - 概念讲解：三张知识卡。“请 Mori 讲解”会生成短讲解并朗读；“换个例子”每次换一组由系统随机生成并计算好的数字，模型只负责讲，算错的风险由代码兜底。
   - 自由答疑：任何阶段都可以在右侧提问。回答里的 [F-xxx] 标记对应资料；点“出处”看原文片段与定位，公开来源可打开原网页。资料没覆盖的问题会明确回答“材料不足”。
   - 情景练习：点“开始买方谈判”后，角色切换为**模拟买家**（徽标与颜色都会变）。买家只按案例条件回应，不说出自己的底线数字，也不替你写方案。练习中可切到“问老师（不计入谈判）”。
   - 提交最终方案：填写单价、首付款比例、交付天数（数量固定 500 件），可选填你算的毛利率。聊天里说“成交”不算数，以提交为准。
   - 反馈：客观核算（收入、成本、毛利、毛利率、加成率；逐项检查卖方条件与模拟买方条件；是否达成练习目标），以及三条表达建议——每条“观察到”都附你的原话和轮次编号，由服务器核对过；没有相关原话就写“未观察到”。没有对话直接提交会显示“证据不足”。
   - 复练：“练我没掌握的部分”根据你的实际错误出题（例如把加成率当毛利率 → 毛利率计算题；卖方条件不满足 → 条件检查题），先答后公布答案。
3. **学习报告**：本次实际对话、最终方案、核算、建议、复练结果、引用资料与版本信息；可“打印 / 存为 PDF”。

### 控制按钮（语义互不混淆）
| 按钮 | 作用 |
|---|---|
| 停止讲话 | 只停声音，文字和阶段保留 |
| 停止生成 | 中止正在生成的回复及其后续朗读，未完成的回复标为“已停止”且不保存 |
| 暂停 / 继续学习 | 冻结生成、朗读与阶段推进；继续后回到原阶段 |
| 结束学习 | 结束本轮，停止所有请求与声音，可查看报告或重新练习 |
| 关闭 / 开启声音 | 只显示文字 |

## 3. 五项比赛能力如何体现
| 能力 | 实现 |
|---|---|
| 数字形象 | 二维 Mori 角色：待命 / 思考 / 讲话 / 出错四态；只在音频真实播放时进入讲话态，嘴型随实时音量；买家角色有独立外观与徽标 |
| 语音或文本交互 | 自由文本输入；服务器中文神经语音逐句朗读（浏览器语音兜底）；可随时打断再问 |
| 知识问答 | 本地检索课程片段 → 模型只依据片段作答 → 服务器剔除伪造引用；资料外如实说“材料不足” |
| 内容生成 | 讲解与例子动态生成（数字由代码生成与核算）；复练题按错误类型生成，答案服务器保留 |
| 教学引导 | 服务端状态机（认识任务→讲解→练习→反馈→复练→完成），答疑是插入动作，答完回原阶段 |

## 4. 技术架构
浏览器（Vue 3）⇄ 课程 API（Fastify，/human/api）⇄ DeepSeek（模型）与 Edge 语音。课程包 `content/course.json` 的 `serverOnly`（买家底线、答案键、角色策略）只在服务器读取，公开接口和前端代码中都没有。会话匿名，归属由 HttpOnly cookie 决定，别人拿到会话编号也读不到报告。

## 5. 换一门课要改什么
替换 `content/course.json`：学习目标、事实片段（带来源与定位）、知识卡、案例（公开/隐藏两部分）、规则参数与复练模板；`rules.ts` 中的条件公式按新案例调整。界面、检索、引用校验、反馈核对、语音与形象无需改动。

## 6. 已知限制
- 课程内容未经教师审核；ICC 摘录为教学引用。
- 没有语音输入（P1）；数字人是二维角色，不是真人视频，也不做精准口型。
- 会话存于内存，服务重启会丢失进行中的学习。
- 朗读依赖微软在线语音的非官方接口；不可用时自动改用浏览器语音或纯文字。
- 未做真实学生试用；不能据此声称教学效果。
